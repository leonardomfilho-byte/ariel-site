- Certificado digital A1 e-CNPJ da empresa: valido ate 01/04/2027.

Testei os dois fluxos OAuth possiveis, com as tres aplicacoes. Nenhum esta
acessivel. Segue o resultado de cada um.


1) client_credentials - o fluxo publicado por voces

Requisicao, exatamente como consta em "Como comecar", passo 4:

    POST https://apis-auth.sefa.pa.gov.br/protocol/openid-connect/token
    Content-Type: application/x-www-form-urlencoded

    grant_type=client_credentials
    client_id=<client id da aplicacao>
    client_secret=<client secret da aplicacao>

Resposta obtida, identica para as tres aplicacoes (HTTP 401):

    {"error":"unauthorized_client",
     "error_description":"Client not enabled to retrieve service account"}

Testado tambem com o client_secret no header Authorization: Basic, com o
mesmo resultado.

Leitura desse retorno: a autenticacao do client foi aceita - credencial
incorreta produziria invalid_client, e nao unauthorized_client. A recusa e
posterior e se refere a configuracao do client: ele nao possui service
account habilitado, condicao necessaria para o client_credentials.

Ou seja, o fluxo publicado na pagina "Como comecar" nao funciona com as
aplicacoes que o proprio portal cria - e nao ha, na area autenticada,
nenhuma opcao visivel para habilitar essa configuracao.


2) authorization_code - a alternativa

Como a semantica do endpoint GET /vinculos ("retorna os vinculos vinculados
ao CPF/CNPJ do usuario presente no token JWT") sugere um token de usuario e
nao de maquina, testei tambem o fluxo de autorizacao, pelo navegador, com o
certificado e-CNPJ instalado:

    GET https://apis-auth.sefa.pa.gov.br/protocol/openid-connect/auth
        ?client_id=<client id da aplicacao>
        &response_type=code
        &scope=openid
        &redirect_uri=https://zeh.web.app/sefa/callback

Resposta obtida, identica para as tres aplicacoes:

    HTTP 403 Forbidden
    Request forbidden by administrative rules.

Leitura desse retorno: o bloqueio e do gateway, anterior ao Keycloak. Uma
redirect_uri nao cadastrada produziria invalid_redirect_uri, e um client
inexistente produziria invalid_client - nenhum dos dois ocorreu. O endpoint
/.well-known/openid-configuration do mesmo host tambem responde 403.


RESUMO

- client_credentials, em /protocol/openid-connect/token:
  HTTP 401 - "Client not enabled to retrieve service account"
- authorization_code, em /protocol/openid-connect/auth:
  HTTP 403 - bloqueado no gateway

Com adesao habilitada e tres aplicacoes ativas, nao ha caminho de integracao
aberto hoje para a API do DEC neste CNPJ.
